# Canvas Explorer — руководство для агентов

Проводник для Windows, в котором у каждой папки может быть **холст**: список файлов становится
окном на бесконечном полотне, а вокруг него можно закреплять живые окна предпросмотра файлов
(изображение, текст, Markdown, аудиоплеер, PDF). Интерфейс тёмный, компактный, с акцентным
цветом из настроек Windows. Язык интерфейса — русский.

Что ещё не сделано и известные проблемы — в [`docs/TODO.md`](docs/TODO.md). Читайте его перед
началом работы: там же записаны решения, которые пользователь уже принял.

---

## 1. Быстрый старт

| Что | Как |
|---|---|
| SDK | .NET 8 SDK (`winget install Microsoft.DotNet.SDK.8`). Целевая платформа `net8.0-windows10.0.19041.0` |
| Сборка (Debug) | `dotnet build src/CanvasExplorer` → `src/CanvasExplorer/bin/Debug/net8.0-windows10.0.19041.0/CanvasExplorer.exe` |
| Сборка в `dist\` | `build.cmd` (Release, framework-dependent). На `dist\CanvasExplorer.exe` смотрит ярлык пользователя на рабочем столе |
| Пересобрать и запустить | `run.cmd [папка]` — закрывает запущенный экземпляр, собирает, запускает |
| Пример для проверки | `samples\Пример` — папка с готовым холстом (Markdown, PDF, WAV, PNG, TXT) |
| Тесты | `test.cmd` — модульные (секунды); `test.cmd ui` — все, включая UI-сценарии (~3 мин, двигают мышь!). См. 8.1 |
| Аргумент командной строки | путь к папке — откроется отдельной вкладкой (если уже открыта — станет активной) |

Перед сборкой закрывайте запущенное приложение (`taskkill /IM CanvasExplorer.exe /F`), иначе exe заблокирован.

Пользовательские данные:
- `%AppData%\CanvasExplorer\settings.json` — окно, ширина боковой панели, плотность строк, открытые вкладки,
  избранное (`Favorites`; `null` = стандартный набор), папки в виде сетки (`GridFolders`), громкость плеера (`AudioVolume`).
- Теги хранятся **в самом файле**: скрытый поток NTFS `<файл>:canvas.tags` (строка на тег: id, имя, цвет, иконка;
  дата «Изменён» при записи не меняется). `%AppData%\CanvasExplorer\tags.json` — список тегов и индекс
  (`files`: путь → id) для счётчиков и просмотра тега; индекс сверяется с потоками при каждом чтении папки.
- `TileScale` в настройках — размер плиток сетки (Ctrl+колесо).
- `<папка>\.canvas.json` (скрытый) — раскладка холста этой папки. Если в папку нельзя писать —
  `%LocalAppData%\CanvasExplorer\layouts\<SHA1 пути>.json`.
- Переменная окружения `CANVAS_EXPLORER_DATA` подменяет обе папки данных (так UI-тесты не трогают
  настройки пользователя). Настройки пишутся через ~1 с после любого изменения, не только при закрытии.

## 2. Стек

- **C# / WPF**, .NET 8, весь UI нарисован самостоятельно (без сторонних тем). Окно — `WindowChrome` без системной рамки.
- **Markdig 1.4.0** — разбор Markdown. **NAudio 2.2.1** — аудио (версии новее требуют .NET 9).
- **Windows.Data.Pdf** (WinRT, через TFM `windows10.0.19041.0`) — рендер PDF.
- **Windows.UI.ViewManagement.UISettings** — акцентный цвет Windows (`AccentLight2`), обновляется на лету.
- Шрифт **Onest** встроен (`Fonts\*.ttf`, OFL). Моноширинный — Cascadia Mono / Consolas из системы.
- Файловые операции — через Shell API (`SHFileOperation`): корзина, отмена, системный прогресс.

## 4. Как это устроено

### 4.1 Главное окно и вкладки (`MainWindow`)
- Вкладка = `FolderTab { Path, Back, Forward }`. `_current` — папка активной вкладки.
- `NavigateTo(path)` → `Show(folder)`: сохраняет холст, обновляет путь/вкладки/боковую панель,
  перезапускает `FileSystemWatcher`, асинхронно читает папку (`LoadItemsAsync`, защищено `_loadVersion`
  от гонок), затем `CanvasView.LoadFolder`.
- Обновление от watcher идёт через `_refreshTimer` (250 мс) → `LoadItemsAsync(keepCanvas: true)`:
  сохраняет выделение, не трогает холст, только убирает окна удалённых файлов.
- `_pendingReveal` — имя, которое надо выделить после следующей загрузки (переход «вверх», переименование, создание).
- Вкладки рисуются заново в `RenderTabs()`; ширина ужимается в `FitTabs()`; drag&drop на вкладку
  переключает её через 550 мс (`_tabHoverTimer`) или переносит файлы в её папку.
- Верхние 38 px окна — заголовок (`WindowChrome.CaptionHeight`): всё кликабельное там должно иметь
  `WindowChrome.IsHitTestVisibleInChrome="True"`.

### 4.2 Холст (`CanvasView`)
- **Режим «без холста»** (нет `.canvas.json` или `Docked = true`): список растянут на всю область,
  тянуть можно только левый/правый край. Если отпустить край, сдвинув его внутрь больше чем на 40 px,
  создаётся холст (`CreateCanvas`).
- **Режим «холст»**: окно списка (`_listFrame`) двигается за строку заголовков колонок и меняет размер
  за любой край. Закреплённые окна — `PreviewWindow` в `World` (Canvas с `ScaleTransform` + `TranslateTransform`).
- **Сворачивание**: если окно списка растянуто почти на всю видимую область (допуск 16 px), холст
  прячется (`CollapseCanvas`): раскладка сохраняется с `Docked = true`, окна выгружаются. Потянули край
  внутрь — окна вернутся. Если закреплений не было, `.canvas.json` удаляется.
- **Магнит** (`SnapList`): края списка прилипают к краям видимой области (16 px / zoom).
  **Привязка** (`_anchors`, `TouchingEdges`, `FollowAnchors`): края, лежащие точно на краях видимой
  области, следуют за изменением размера окна приложения. Любой пан/зум привязку снимает.
- При каждом входе в папку вид сбрасывается в начало (pan 0,0, zoom 1). Поле `view` в файле
  пишется, но **не** читается — так решил пользователь.
- Закрепление (`Pin`) никогда не двигает вид; новое окно ставится в видимую часть холста (`NextSpot`).
- Закрепления файлов, которых нет при открытии папки (переименованы, диск не подключён), хранятся в
  `_missing` и пишутся обратно в раскладку; появился файл — окно возвращается (`SyncItems`).
  Счётчик «N на холсте» считает только существующие файлы.
- Панель масштаба в углу появляется только над **пустым** холстом; угловая зона сама ввод не принимает,
  поэтому список и окна в правом нижнем углу остаются кликабельными. Средняя кнопка панорамирует через
  всплывающее (не preview) событие — средний клик по папке в списке открывает вкладку и на холсте.
- Клик в окно списка снимает выделение с окна на холсте (иначе Del из списка откреплял бы его).
- Сохранение — с задержкой 500 мс (`ScheduleSave`), немедленно — `SaveNow()` (смена папки, закрытие).

### 4.3 Плавающие окна (`FloatingFrame`)
- Перенос: только за элементы с `FloatingFrame.IsDragHandle="True"` (кнопки и поля ввода исключаются).
- Ресайз: зона 6 px у разрешённых краёв (`Edges`), курсор через `Mouse.OverrideCursor`.
- Подсветка: `EdgeGlow.Show(edges)` — схваченная сторона целиком в акценте, соседние гаснут к углам.
  Во время подсветки рамка выделения скрыта. `EdgeGlow` прячется через `Hidden`, **не** `Collapsed`
  (градиенту нужен реальный размер).
- `OnMouseWheel` помечает событие обработанным: колесо внутри окна никогда не двигает холст.
- `Snap` — необязательный магнит (используется только для окна списка).

### 4.4 Список (`FileListView`)
- Шаблоны строк `RowL` (44 px), `RowM` (30), `RowS` (23) и плитки `Tile`; переключаются в `ApplyMode()`.
- Выделение мышью реализовано вручную (`OnPreviewDown/Move/Up`): нажатие на **значок или имя**
  (элементы с `Tag="grab"`) — выбор и перетаскивание файла; нажатие на остальную часть строки или пустое
  место — рамка выделения (`Marquee`). Ctrl/Shift работают как в Проводнике.
- Drag&drop: наружу — `DataFormats.FileDrop`; внутрь — правила `Shell.DropEffect`
  (тот же диск → перемещение, другой → копирование, Ctrl — копия, Shift — перенос); бросок на строку-папку
  кладёт внутрь неё.
- Миниатюра при наведении на значок изображения — `Chip_ToolTipOpening`.
- При смене папки (не при обновлении) прокрутка сбрасывается наверх, проигрывается `PlayEnter()`.
- Полоса прокрутки списка прижата к краю: зона изменения размера у правого края окна списка 4 px
  (`FloatingFrame.RightGripZone`), полоса начинается сразу за ней (`ListScrollBar`, правый отступ списка 3 px).
- Ctrl+колесо в сетке — размер плиток (`TileScale` 0.6–3, общий; холст не масштабируется); превью
  догружаются крупнее, когда плитки растут.
- Список или сетка — **для каждой папки свой** (`AppSettings.GridFolders`, ключ — путь; `ShowAsGrid` из
  `MainWindow.Show`, выбор пользователя → `Host.SetFolderGrid`). Плотность строк общая.
- В сетке у изображений и видео — превью от Windows (`ShellThumbnails`, `LoadThumbnails`), у видео значок ▶;
  нет превью (нет обработчика у формата) — остаётся чип типа.
- После имени — отметки тегов (`FileItem.Tags`, `TrailPanel`); меню файла «Теги ›» с галочками и «Новый тег…».

### 4.4а Левая панель и теги (`Sidebar`, `TagStore`)
- Разделы: «Избранное» (порядок и имена в настройках; добавить — меню папки, меню пустого места,
  бросок папки на заголовок «Избранное»; убрать/переименовать/вверх/вниз — меню строки; переставить —
  перетащить строку на другую), «Расположения» (перестраивается по `WM_DEVICECHANGE`), «Теги» + «Новый тег».
- Тег в панели: клик — просмотр тега (вкладка с адресом `tag:<id>`: файлы из любых папок, без холста,
  без вставки и создания; `IsVirtualView`), средняя кнопка — во вкладке, бросок файлов — назначить тег.
  Бросок файлов на вкладку тега — тоже назначить.
- Хранение (решение пользователя): **вместе с файлом** — поток NTFS `:canvas.tags`, который переезжает с файлом
  при любом переименовании/переносе в пределах NTFS и копируется Проводником. `TagStore.Reconcile(папка)`
  (из `MainWindow.Enumerate`) берёт теги из потоков (неизвестный тег создаётся по данным из потока — например,
  файл с другого компьютера), восстанавливает поток, потерянный при сохранении «через временный файл», и
  убирает из индекса ушедшие файлы. Где потоков нет (FAT, часть сетевых дисков) — работает только индекс.

### 4.4б Плеер (`AudioEngine`, `MiniPlayer`)
- Воспроизведение принадлежит `AudioEngine.Current`, а не окну: окно аудио на холсте (`AudioPreview`) и
  мини-плеер — только «виды». Откреплённое окно, другая папка или закрытая вкладка музыку не останавливают;
  остановить — × в мини-плеере (или закрыть приложение). Файл держится открытым только загруженный в плеер.
- Мини-плеер появляется при первом запуске звука, стоит под тегами; `SidebarStack` отдаёт разделам место,
  оставшееся после плеера, поэтому при длинном списке разделы прокручиваются, а плеер неподвижен.
- Громкость и повтор общие (громкость — в настройках). Видеоплеер ещё не сделан; его место — там же.

### 4.5 Предпросмотры (`Previews/`)
Добавить новый тип:
1. Класс-наследник `PreviewContent`. Переопределите по необходимости: `PreferredSize`, `SupportsZoom`/`Zoom`/`SetZoom`,
   `IsDirty`, `HeaderExtra` (элемент в заголовке окна), `HandleKey`, `Unload` (освободить файл, сохранить).
2. Вызывайте `RaiseState()` при изменении зума/«грязности», `RaiseNaturalSize()` — когда узнали пропорции.
3. Зарегистрируйте в `PreviewFactory.Create`.

Редактируемые тексты сохраняются через `TextFile.Write` (временный файл + `File.Replace`) с задержкой ~0.7–0.8 с.

Изменения файла другой программой: `MainWindow` собирает имена из `FileSystemWatcher` (в т.ч. «запись
во временный файл + переименование поверх») и вызывает `PreviewContent.OnFileChanged()`. Текст и
Markdown сравнивают `FileStamp`: без несохранённых правок — перечитывают файл (каретка и прокрутка
сохраняются), с правками — спрашивают «Да — оставить мои / Нет — загрузить с диска». Перед каждой
записью версия на диске сверяется, так что чужие изменения молча не затираются. Изображение перечитывается.

## 5. Формат `.canvas.json`

```json
{
  "version": 1,
  "docked": false,
  "view": { "x": 0, "y": 0, "zoom": 1 },
  "list": { "x": 0, "y": 0, "w": 420, "h": 740 },
  "items": [
    { "name": "Озеро.png", "x": 450, "y": 16, "w": 360, "h": 262, "zoom": 1 }
  ]
}
```
Координаты — в единицах холста (DIP при zoom = 1). Файлы привязаны **по имени** в этой же папке.
Скрытый файл нельзя открыть через `FileMode.Create` — пишите через `OpenOrCreate` + `SetLength(0)` (см. `LayoutStore`).

## 6. Решения по дизайну (согласованы с пользователем, не менять без спроса)

- Тёмная тема: панели `#1B1B1B`, холст `#0C0C0C`, окна `#202020`, обводки `#2A2A2A`, текст `#EDEDED`.
  Все цвета — ресурсы в `Themes/Dark.xaml`; в коде используйте `SetResourceReference`, а не литералы.
- Акцент — только из Windows (`AccentBrush`, `AccentSoftBrush`, текст на акценте — чёрный `OnAccentBrush`).
- Скругления «как в Windows»: 4–8 px, без «таблеток». Исключения по просьбе пользователя: круглая
  кнопка «плей» и цветные точки тегов.
- Не «как у Apple»: свои компактные кнопки окна в стиле Windows справа сверху, шрифт Onest.
- Нет общих полос прокрутки окна: холст бесконечный, прокручиваются только списки/документы внутри окон.
- Ручек на краях нет — вместо них градиент по обводке (см. 4.3). Панель масштаба холста в правом
  нижнем углу скрыта, пока курсор не подойдёт к углу.
- Контекстные меню — компактный вертикальный список (строки 24 px), вырезать/копировать/вставить — пунктами.
- Анимации короткие и простые (`Anim.Short`, сейчас 140 мс; пользователь просил «15–30 мс»,
  это 1–2 кадра — оставлено 140 мс, константа в одном месте).
- Теги: у тега **либо** цветная точка, **либо** иконка (палитра и 16 иконок — из макета); в панели точка 10 px /
  иконка 14 px, в строках 8 / 12 px.
- Громкость плеера общая для приложения: новый плеер стартует с последнего выставленного уровня.
- Макеты: https://claude.ai/artifact/BmTDDZnH8qcu8TGAdtA7sF (итог — артборд «Тёмная · вариант A»).

## 7. Управление

| Где | Действие |
|---|---|
| Окно | Alt+←/→ или боковые кнопки мыши — назад/вперёд; Alt+↑ — вверх; F5 — обновить; Ctrl+L / F4 — ввести путь; Ctrl+F — поиск |
| Вкладки | Ctrl+T — новая; Ctrl+W, крестик, средняя кнопка — закрыть; Ctrl+(Shift+)Tab — переключить; средняя кнопка по папке — открыть во вкладке |

## 8. Правила работы для агентов

- **Git**: пользователь просит коммит **до** начала каждого раунда изменений и **после** него.
  Коммиты на русском или английском, с трейлером `Co-Authored-By`, если ваша среда его требует.
  `dist/`, `bin/`, `obj/` в `.gitignore`; бинарные файлы помечены в `.gitattributes`.
- После изменений: `dotnet build` без ошибок и предупреждений, `test.cmd` (при изменениях интерфейса —
  `test.cmd ui`), затем `build.cmd`, чтобы ярлык пользователя запускал свежую версию.
- Нашли ошибку — сначала тест, который её воспроизводит, потом исправление.
- Не пишите тестовые файлы в `samples\Пример` и в реальные папки пользователя — создавайте
  временную папку. Файловые операции приложения идут в настоящую корзину.
- Тексты интерфейса — на русском, с правильными склонениями (`Format.Plural`).

### 8.1 Тесты (`tests/CanvasExplorer.Tests`, xUnit)

- `Unit/` — сервисы без интерфейса: `Format`, `TextFile` (кодировки, обрезка больших файлов), `FileStamp`,
  `Shell.DropEffect`, `LayoutStore`, `FileItem`, проверка имён, `MarkdownFlow` (Render → Serialize без потерь;
  WPF-код выполняется на STA-потоке через `Sta.Run`).
- `UI/` — сценарии на **настоящем** `CanvasExplorer.exe` (`[Trait("Category", "UI")]`, коллекция «UI», по одному).
  `Infrastructure/AppSession` создаёт папку `%TEMP%\CanvasExplorerTests\ui-*`, запускает приложение с
  `CANVAS_EXPLORER_DATA` и фиксированным окном, находит элементы через UI Automation (`x:Name` = AutomationId;
  строки списка — по имени файла; окна холста — `AutomationId="PinnedWindow"`, окно списка — `"ListWindow"`),
  а ввод делает настоящими мышью и клавиатурой (`Infrastructure/Input`: клавиши — по VK-кодам, текст —
  Unicode, раскладка не важна). Результат проверяется по UIA, по файлам и по `.canvas.json` / `settings.json`.
- Новый сценарий: `AppSession` в поле класса теста (Dispose убирает процесс и папку), подготовка
  (`WriteFile`, `MakeDir`, `WriteLayout`), `Launch()`, действия, `Wait.Until(...)` вместо `Sleep`.
- Подводные камни: элемент окна из UIA, взятый слишком рано, — пустой Win32-прокси (переполучать, см.
  `Launch`); синтетическое нажатие Alt переводит окно в режим системного меню — активируйте окно кликом
  по заголовку; после ручного отката файла MSBuild может не пересобрать проект (старая дата файла) —
  `--no-incremental`; тесты вставки пользуются буфером обмена пользователя.

### 8.2 Ручная проверка интерфейса (`tools/ui/`)
Скрипты PowerShell, которые двигают настоящую мышь (предупредите пользователя) и снимают скриншоты:

| Скрипт | Назначение |
|---|---|
| `shot.ps1 -Out a.png` | снимок окна приложения (PrintWindow; меню и тултипы **не** попадают) |
| `screen.ps1 -Out a.png [-X -Y -W -H]` | снимок области экрана над окном (меню попадают) |
| `mouse.ps1 -X1 -Y1 [-X2 -Y2] [-Right] [-Ctrl]` | клик или перетаскивание (координаты от левого верхнего угла окна) |
| `path.ps1 -Points "x,y;x,y,waitMs;..." [-Button left/middle/right]` | перетаскивание по точкам с паузами (drag&drop, наведение на вкладку) |
| `hover.ps1 -X -Y -Out a.png` | навести курсор и снять окно |
| `vkey.ps1 -Combo "ctrl+t"` | сочетание клавиш по кодам клавиш |
| `keys.ps1` | SendKeys и прокрутка колесом |

Подводные камни: у пользователя русская раскладка — `SendKeys` не набирает латинские буквы в
сочетаниях (`^t` не сработает) и кириллицу в полях; используйте `vkey.ps1`. Не оставляйте открытым
меню/диалог перед следующим кликом — клик попадёт в пункт меню.

### 8.3 Подводные камни WPF, на которые уже наступали
- В классах-наследниках `Window` имя `Icon` — это свойство окна; используйте алиас `UiIcon`.
- `FontFamily` с `pack://application:,,,` нельзя писать в списке через запятую — используйте `/CanvasExplorer;component/Fonts/#Onest`.
- Подавление контекстного меню после пана ПКМ: `AddHandler(ContextMenuOpeningEvent, …, handledEventsToo: true)` + сброс флага через `Dispatcher.InvokeAsync(..., Input)`.
- Выделение окна на холсте должно всегда забирать фокус (`CanvasView.Select`), иначе Del уходит в список и удаляет файлы.
- `MediaFoundationReader` и `Windows.Data.Pdf` держат файл открытым, пока окно закреплено.
- Элемент с `Background="Transparent"` перехватывает клики, хотя «невидим»; так же и элемент с `Opacity=0`.
  Для зон наведения — фон `null` и переключаемый `IsHitTestVisible`.
- `PreviewMouseDown` на предке срабатывает раньше обработчиков потомков: пан средней кнопкой на нём
  «съедал» средний клик по папке в списке.
- Флажки задач в Markdown слушают `Checked`/`Unchecked`, а не `Click` — иначе переключение с клавиатуры
  или экранным диктором не сохраняется.
- Кнопки-иконки получают имя для экранного диктора из `ToolTip` (сеттер в стиле `IconButton`).
